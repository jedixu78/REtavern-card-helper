### 主题 A：大量「已建成但断线」的半成品（最高 ROI 修复区）

| A2 | `/wizard/:id` 就地编辑模式（含 createdAt 保留、更新 toast） | 全站无任何 UI 导航到该路由，库「编辑」永远 fork 新卡 | low |

### 主题 B：数据安全信任危机（P0 修复类）

1. **草稿箱加载被旧自动草稿静默覆盖**（high/broken）：DraftsPage 经 `/wizard?draftId=X` 进入后，WizardPage 立即 `navigate('/wizard')` 清参数 → 触发加载 effect 重跑 → 杀掉防抖保存 → 内容被换成旧的 'new' 自动草稿。用户点开的草稿显示成另一份内容。旁证：同文件工坊导入处特意注释改用 `replaceState` 规避此问题，说明作者已知机制。（WizardPage.tsx:354-358、useWizardState.ts:102-168）
2. **无整库备份**且横跨两个存储：卡片/草稿/聊天在 IndexedDB，工坊状态/背景图/预设/主题在 localStorage。清浏览器数据 = 全部创作丢失；未调用 `navigator.storage.persist()`，浏览器存储压力下可整体回收。备份方案必须同时覆盖两者。
3. **「编辑=fork」组合事故链**：正在写新卡 → 顺手改库里旧卡一个错别字 → 「编辑」fork 且静默覆盖进行中的自动草稿 → 新卡内容被顶掉、无版本可回。（三个域的发现拼合）
4. **导入即破坏**：第三方 ST 卡导入时立即走 `cardToDraft→assembleCard` 规范化，`mes_example`、第三方 regex_scripts、自定义 extensions 被静默丢弃；`at_depth` 条目降级为 `after_char`。
5. **手动草稿版本拒载**：自动草稿有 V4→V5→V6 迁移，手动草稿 `version !== 6` 直接报「加载失败」——下次 bump 版本会锁死存量草稿。
6. localStorage 5MB 是共享战场：一张 base64 高清背景图就能挤掉小说工坊的 checkpoint 空间。

### 主题 C：验证闭环缺失（试聊价值问题）

试聊不模拟：世界书关键词触发（绿灯条目完全不生效）、正则脚本替换（状态栏/直播间显示原始占位符）、MVU 变量演算（开场白直接显示 EJS 源码）、分阶段调度。**本工具主打产出（状态栏卡/分阶段卡）在自己的试聊里零验证价值**，用户只能导出到 ST 里试错。叠加：非流式、无停止按钮、无会话管理、system prompt 被写卡预设污染。

单点修复定位（跨域盲区拼合）：「生成不可取消」全站九个入口同根——前端 `ai-service.ts` 无 AbortController，而**服务端 ai-proxy.js 已实现**（仅用于超时），修一处全站受益。

### 主题 D：规范覆盖缺口（对照生态调研）

- `mes_example` 全链路缺失——**V2/V3 规范必填字段**，导出的卡不含、导入的被丢弃。
- V3 新字段零覆盖：`nickname`/`assets`/`creator_notes_multilingual`/`source`/`group_only_greetings`；charx（zip）完全不支持。
- 独立世界书 JSON（ST world info 格式）无法导入导出——竞品与社区的基本预期。
- MVU 变量定义导出只存数量不存内容，往返后 schemaSections 重建为空。
- quality-checker 评分偏结构计数，无 token 预算维度（JanitorAI 社区对 token counter 的呼声是长期热点）。

### 主题 E：安全与部署

1. **公网代理是开放中继**（已亲自核实）：`server/routes/ai-proxy.js` 无鉴权、接受前端传入的任意 upstream URL——README 的 workers.dev 在线站可被第三方白嫖转发流量、用于 SSRF 探测。
2. 默认背景图依赖第三方内部生图接口（`trae-api-cn.mchost.guru`），随时可能失效。
3. PWA 伪离线：main.tsx 每个新会话注销 SW、清缓存并强制 reload，离线冷启动必然白屏。
4. MVU 运行时 CDN 依赖硬编码未锁版本，上游变更可让所有已导出卡片失效。
5. 直播间初始评论注入 `<script>` 时未转义 `</script>`，可破坏/注入生成的 HTML。

### 主题 F：文档失实

- `社区介绍.md` 两处声称 **MIT**，LICENSE/README 实为 **GPL-3.0**（已核实）；站点 URL 两处不一致（vercel.app vs workers.dev）；「七步向导」实为 9 步；「三种模板」实为 7 个。
- 根目录调试遗留（`_analyze2.mts`、`_test_card.json`、`debug-worldbook-empty-stream.md` 等）污染仓库。

## 三、生态调研要点（外部依据摘要）

- **SillyTavern 约 6 周一版**：1.15 Macros 2.0（旧宏引擎将淘汰）；1.16 条件宏/scoped macros；1.17 `/char-create` 系列（**角色卡可编程化创建**——编辑器可从「导出文件」升级为「一键同步进 ST」）；世界书方向是放置与管理（outlet、relink）而非新触发机制。
- **V3/charx 双雄格局**：完整实现仅 ST 与 RisuAI；分发平台仍以 V2 为安全基线；ST 写卡时 V2+V3 双 chunk。「一次编辑、三种输出（V2 PNG / V3 PNG / charx）」可覆盖全部受众。
- **中文进阶卡事实标准**：酒馆助手 + MVU + EJS + 状态栏 HTML 五套体系叠加，学习成本极高（教程生态火爆即门槛证据）——本工具的 MVU 可视化正踩在最大差异化空间上，竞品 CardForge（Electron，157 stars）已验证方向。
- **「本地优先 + 备份」是能打动作者的卖点**：类脑 Chaos 区误删损失约两年 80% 卡资源、Backyard AI 无预警关停，跨社区共识是「平台会死、卡要能跑」。
- **token 预算可视化 + 世界书触发模拟**目前没有编辑器做好——机会窗口。

## 五、工程配套（与路线图并行）

1. **补测试优先级**：`syncCharacterEntries`（>2000 字分块/ID 复用/删除语义）、草稿 V4→V6 迁移与拒载、`png-service` 手写 CRC/chunk 解析、`draft-service` 时序——全是本次发现高危 bug 的无测试区。纯逻辑均可低成本单测。
2. **每阶段验收线**：typecheck + 全量测试 + build 三绿(现状:351 测试全过、0 lint 错误)。
3. **版本体系协调**：WIZARD_DRAFT_VERSION / 工坊 localStorage 版本 / Dexie 表结构三套各自演进,做备份功能(P0-3)时一并定义兼容矩阵。
